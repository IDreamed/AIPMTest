# Axure 前端化需求澄清清单

更新时间：2026-07-22

## 1. 结论

当前资料已经足够确认一期的端侧边界、主要页面和大部分展示字段，可以开始把 Axure 中的教师教学功能迁入 React 原型。

但还不足以直接完成最终版交互。当前主要缺口不在页面数量，而在以下几类业务口径：

- 教师端信息架构已确认不设置教师工作台，默认进入教学资源；组课管理和我的课程暂按当前原型保留两个入口。
- 课程、课时、课件、课程试卷之间的关系和编辑边界。
- 练习试卷、作业试卷、考试专用试卷的用途隔离。
- 班级专业、文化课公共访问和教师班级权限。
- 班级作业的发布、编辑、作答、批阅、出分和解析时机。
- 状态名称、删除语义、历史数据保留等跨页面规则。

因此，后续工作应采用“先确认对象关系和状态，再逐页前移”的方式，不能仅按 Axure 页面外观复刻。

## 2. 事实来源与使用顺序

发生冲突时，按以下顺序判断：

1. 用户本轮及后续明确确认的规则。
2. `考试系统修改.md`。
3. `项目整体PRD.md`。
4. `一期项目交付目标.md`。
5. `PROJECT_MAP.md`。
6. `后台功能与设计说明.md`。
7. `Axure后台页面功能清单.md` 和 Axure 扫描字段。
8. 当前 React 源码和 mock 数据。
9. `BACKEND_CAPABILITIES_CHECKLIST.md` 仅作为历史问题索引，不覆盖新口径。

Axure 用于提取已存在的字段、操作、弹窗和流程，不作为教师端前台的视觉设计目标。React 原型需要保留业务语义，但使用现有前台设计系统重新组织。

## 3. 当前项目理解

### 3.1 端侧边界

| 端 | 一期职责 | 不迁入 React 的内容 |
|---|---|---|
| 公开访问端 | 首页、资讯、推荐课程试看、报考指南、虚拟实训入口 | 平台配置与审核 |
| 学生端 | 课程学习、作业、正式考试、试卷练习、错题、答疑、学习记录 | 学校、班级和资源授权配置 |
| 教师端 | 看授权资源、组课、维护课程和试卷、派课、作业、批阅、学情、答疑 | 教师账号、学生审核、分班和角色权限配置 |
| 平台运营后台 | 资讯和首页推荐课程 | 完整平台管理能力 |
| 学校管理后台 | 教师、学生、班级、审核、角色和权限配置 | 日常教学执行动作应迁出 |
| 平台管理后端 | 专业、资源库、知识点、资源、题库、审核、学校授权、平台联考 | 不在 React 中重做 |

### 3.2 核心业务关系

```text
科目/专业
├─ 资源库（一个科目/专业可有多个资源库）
│  └─ 最多四级知识点
│     ├─ 教学资源
│     └─ 题目
├─ 课程
│  ├─ 课程基础信息
│  ├─ 课时目录
│  ├─ 课时内容/练习
│  ├─ 课件
│  └─ 课程试卷
└─ 试卷
   ├─ 练习试卷
   ├─ 作业试卷（是否独立仍待最终确认）
   └─ 考试专用试卷

班级
├─ 绑定一个专业大类
├─ 绑定学生、班主任和任课教师
├─ 接收教师派发的课程
├─ 接收教师发布的班级作业
└─ 形成课程学习、作业、答疑和学情记录
```

当前已确认的关系：

- 资源和题目绑定在“科目/专业 -> 资源库 -> 最多四级知识点”下。
- 课程与试卷直接绑定科目/专业，不绑定资源库。
- 资源库和知识点用于定位资源、题目，以及课时选材和试卷选题。
- 教师只能查看学校授权范围内的资源、题目、课程和试卷。
- 平台课程只读，本校课程允许教师在权限范围内维护。
- 班级作业属于学习中心，不进入学生正式考试中心。
- 平台联考属于正式考试，只能使用考试专用试卷或独立考试组卷。
- 学生答疑是按时间、发送人和消息内容展示的一对一留言记录，不设置独立提问标题。
- 原型标注入口保留；标注采用非侵入式浮层，只记录确认后的设计和开发规则。

## 5. 已发现的当前实现偏差

这些问题已有明确证据，不需要等待业务澄清即可在后续修改中处理：

1. 已确认教师端不设置独立工作台，默认进入“教学资源”；旧文档中的工作台描述不再作为交付要求。
2. 当前教师端把“组课管理”和“我的课程”设为两个一级入口，但 Axure 原始结构更接近“课程列表 -> 新建/编辑 -> 课时/课件/试卷管理”。两入口存在重复。
3. 当前课程和试卷 mock 主要依赖名称字符串关联，没有统一的专业、资源库、课程、试卷、班级 ID 关系，跨页面容易出现字段不一致。
4. 当前试卷数据没有明确的 `练习/作业/考试专用` 用途字段，同一批试卷被课程、练习和作业复用，无法验证用途隔离。
5. 当前新建班级作业页没有班级字段，只包含作业名称、专业、开始时间、结束时间和试卷；直接打开该路由时无法判断作业属于哪个班级。
6. 当前教师班级 mock 中存在“文化课班级”，与“班级绑定一个专业大类，文化课向所有班级学生开放”的新规则冲突。
7. 已统一使用“作业”，旧称“智慧作业（班级测试）”不再作为当前产品文案。
8. 教师端当前没有独立“考试中心”；用户修订文档要求教师侧有考试统计、排名、薄弱知识点和试卷查阅，现有 PRD 又把平台联考管理留在后端。
9. 当前组课页面已展示目录、课件和课程试卷，但课时内容来源、知识点关联、课时练习限制和课件是否独立于课时没有形成统一规则。
10. 当前教师侧多个“随机组卷、试题管理、保存、派课、批阅”操作仍是演示反馈，没有完整配置字段和状态变化。

## 6. 第一批必须确认的问题

以下问题会改变页面树、一级导航或核心数据结构，建议先确认。

### P0-1 教师端一级导航（已确认）

当前一级导航确认为：

```text
教学资源
我的课程
试卷管理
我的班级
考试结果（如教师需要查看平台联考结果）
```

建议：“组课管理”作为“我的课程”的新建/编辑流程，不再独立作为一级菜单；班级派课、班级作业、学生管理、答疑作为“我的班级”下的班级级功能。

不设置独立教师工作台，教师端默认进入“教学资源”。

### P0-2 教师考试中心的边界

需要确认教师端“考试中心”是以下哪一种：

1. 只读查看自己任教学生参加的平台联考结果、排名和薄弱知识点。
2. 教师可以创建或发布正式考试。
3. 实际只需要“班级作业统计”，不需要独立教师考试中心。

建议普通教师只读查看与自己班级相关的联考结果；正式考试创建、审核和发布继续留在平台管理后端。

### P0-3 班级与文化课权限

需要确认：

- 班级是否只能绑定一个专业大类，不能建立“语文班、数学班、英语班”这类文化课班级。
- 所有已入班学生是否自动获得语文、数学、英语的课程、练习试卷和考试访问权。
- 文化课课程是否可以派给所有专业班级，专业课课程只能派给专业匹配的班级。
- 学生是否始终只有一个当前学校和一个当前班级，不支持切换。

### P0-4 教师与班级的权限关系

需要为以下角色分别确认可见范围和可操作范围：

| 角色 | 查看班级 | 派课 | 布置作业 | 批阅 | 看学情 | 回答答疑 |
|---|---|---|---|---|---|---|
| 学校管理员 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 |
| 教务管理员 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 |
| 班主任 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 |
| 任课教师 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 | 待确认 |

不能继续使用“自己创建的班级才可管理”作为主要规则。

### P0-5 试卷用途

需要最终确认三类试卷：

| 用途 | 谁创建 | 学生自由练习 | 可用于课程 | 可用于作业 | 可用于正式考试 |
|---|---|---|---|---|---|
| 练习试卷 | 平台/学校教师 | 是 | 是 | 待确认 | 否 |
| 作业试卷 | 学校教师 | 否 | 待确认 | 是 | 否 |
| 考试专用试卷 | 平台后端 | 考前不可见 | 否 | 否 | 是 |

重点确认“作业试卷”是否作为独立用途落地。若确认独立，教师端新建试卷必须选择用途，学生试卷练习页必须排除作业卷和考试卷。

### P0-6 课程试卷的含义

需要确认课程中的“试卷”究竟是：

1. 从同专业的练习试卷库中绑定一套试卷。
2. 课程内独立创建的课程练习。
3. 两者都支持，并在课程详情中分开展示。

同时确认课程试卷是否出现在学生“试卷练习”、是否进入错题本、是否计入学习记录，以及是否允许教师把课程试卷直接用于班级作业。

### P0-7 班级作业创建方式

需要确认作业是从班级详情进入，还是允许从全局作业列表新建。

建议两种入口最终进入同一表单：

- 从班级进入时自动锁定班级和专业。
- 从全局进入时先选班级，再由班级自动带出专业。
- 试卷只显示与专业和用途匹配、已启用的作业试卷。

还需统一时间规则：使用“开始时间 + 结束时间”，还是“开始时间 + 作答时长”。目前资料两种写法并存。

### P0-8 状态和删除规则

需要统一以下状态：

- 课程：草稿、上架、下架、连载中、已完结之间的关系。
- 试卷：启用/关闭与上架/下架是否为同一组状态。
- 作业：未开始、进行中、已结束、待批阅、已出分分别属于作业状态还是学生提交状态。
- 答疑：待回复、已回复、待补充、已关闭是否全部需要。

删除课程、试卷、派课和作业时，还需明确是逻辑删除、下架、取消关联还是彻底删除，以及历史学习/作答记录是否继续可见。

## 7. 第二批流程字段问题

这些问题不阻断页面树，但会影响弹窗和详情页完整度。

### P1-1 课程与课时

- 新建课程是否需要：专业、名称、封面、介绍；是否还需要创建人、连载状态、排序。
- 编辑课程时专业是否永久不可修改。
- 新建课时的必填字段：名称、类型、排序、资源来源、知识点、时长、试看、练习。
- 是否只有慕课、微课、音频可以添加课时练习。
- 课时选择资源时是否先按课程专业筛资源库，再按四级知识点选择素材。
- 平台课程是否只能查看，还是允许“复制为本校课程”。
- 本校课程是否需要审核后才能上架。

### P1-2 课件

- 课件是否独立于课时，还是必须挂在某个课时下。
- 支持 PDF、PPT、Word、图片、音视频中的哪些类型。
- 教师能否本地上传，还是一期只从授权资源库选择。
- 学生查看课件是否记录状态和学习时间。

### P1-3 组卷

- 固定卷是否按大题组织题目，是否支持题目排序和每题分值。
- 随机卷需要哪些规则：资源库、知识点、题型、难度、数量、单题分值。
- 试卷分类最终枚举：一轮复习、二轮专题、三轮冲刺，还是还包含模拟测试、真题汇编等。
- 新建试卷是否必须设置总时长和及格分；若不在基础信息中设置，由哪个环节设置。
- 已被课程、作业或考试引用后，哪些字段仍可编辑。

### P1-4 作业和批阅

- 作业开始前是否可修改全部字段，开始后锁定哪些字段。
- 学生是否可以保存进度和继续作答。
- 客观题是否提交后自动评分；填空题是否自动评分。
- 简答题和综合题主观子题是否必须人工批阅。
- 作业结束后立即显示客观分，还是必须等教师完成批阅并发布成绩。
- 解析是提交后、结束后还是出分后可见。
- 作业错题是否进入错题本，作业结果是否进入学习记录。
- 班级作业是否需要班级内排名和导出。

### P1-5 学情

- 学情只展示学生明细，还是还需要班级、课程、知识点三个汇总维度。
- “薄弱知识点”来自作业、课程练习、试卷练习还是正式考试。
- 一期是否允许展示需要后台聚合计算的完成率、平均分和知识点统计。
- 教师能否查看学生正式考试详情，还是只能查看成绩摘要。

### P1-6 答疑

- 学生只能从课程/课时发起，还是允许从“我的答疑”直接新建无上下文问题。
- 是否允许关联具体题目。
- 是否支持图片或附件。
- 谁可以回复：该课程任课教师、班主任，还是所有有班级权限的教师。
- “待补充”由教师设置还是学生追问后自动产生。

## 8. 学生端仍需统一的口径

1. 作业状态、删除语义和历史记录保留规则的最终接口口径。
2. 当前考试中“即将开始”应按开始时间升序还是倒序。通常应让最早开始的排在前面。
3. 考试记录文档写“按时间正序”，需确认是最早记录优先还是最近记录优先。
4. 资讯详情最终使用独立页面还是弹窗。
5. 课程完成和课时完成的判定条件。
6. 学习记录记录哪些动作，是否仅记录音视频课时。
7. 错题来源是否包含课程练习、试卷练习、班级作业和正式考试全部四类。
8. 正式考试公示后的排行范围、脱敏、搜索和分页规则。

## 9. 可后置的问题

以下内容不应阻塞第一轮页面重组：

- AI 命题生产能力。
- Word 批量导入和真实文件解析。
- 高级随机组卷算法。
- 跨校复杂统计和经营看板。
- 真实文件上传、转码和在线预览服务。
- 资源、题目和试卷的完整版本管理实现。
- 虚拟实训和报考指南的深层业务。

## 10. 建议的确认和实施顺序

1. 确认教师端一级导航和教师考试中心边界。
2. 确认班级专业、文化课访问和教师班级权限。
3. 确认试卷三用途、课程试卷和作业试卷关系。
4. 确认班级作业创建、时间、批阅、出分和解析规则。
