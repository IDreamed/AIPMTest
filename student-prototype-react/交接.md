## 1. 项目概况

本项目是“职教高考学生端 React 原型”，用于承接学生端、考试中心、学习中心、题库练习、个人中心，以及补充的平台运营后台原型。

项目性质是前端原型，不包含真实后端、接口请求、鉴权服务或数据库。当前数据全部来自本地 mock。

主要目标：

- 给产品、设计、研发对齐页面结构、字段、状态和交互闭环。
- 模拟不同学生身份下的页面权限和可见内容。
- 补充平台运营后台的资讯管理和首页推荐课程管理原型。

## 2. 如何运行项目

本电脑环境已经配置好，不需要重新安装 Node.js。

### 2.1 进入项目目录

打开 Windows 终端或 PowerShell，进入项目目录：

```bash
cd /d D:\projects\student-prototype-react
```

如果使用 PowerShell，也可以输入：

```powershell
cd D:\projects\student-prototype-react
```

### 2.2 启动项目

执行：

```bash
npm run dev
```

启动成功后，终端里通常会出现类似地址：

```text
http://127.0.0.1:5173/
```

复制这个地址到浏览器打开即可。

### 2.3 常用访问入口

浏览器打开项目后，可以直接访问这些地址：

```text
首页：http://127.0.0.1:5173/#/
考试中心：http://127.0.0.1:5173/#/exams
学习中心：http://127.0.0.1:5173/#/learning
题库练习：http://127.0.0.1:5173/#/papers
运营后台：http://127.0.0.1:5173/#/admin
```

页面右上角有“演示控制”，可以切换游客、注册用户、班级学生身份，也可以进入运营后台。

### 2.4 停止项目

回到运行 `npm run dev` 的终端窗口，按：

```text
Ctrl + C
```

如果终端询问是否终止，输入 `Y` 后回车。

### 2.5 常见问题

- 页面打不开：先确认 `npm run dev` 的终端没有关闭。
- 地址不是 `5173`：以终端实际显示的地址为准。
- 修改代码后页面没变化：刷新浏览器；如果还不行，停止后重新执行 `npm run dev`。
- 只想看原型：不要执行 `npm run build`，直接 `npm run dev` 即可。

## 7. 当前业务范围

### 6.1 首页和推荐课程

文件：`src/pages/HomePages.jsx`

包含：

- 首页推荐课程。
- 资讯入口。
- 推荐课程试看页。
- 推荐课程试看页中的“申请入校”按钮会打开全局申请入校弹窗。

注意：

- 推荐课程不展示价格。
- 试看课程只做视频试看原型。
- 申请入校只支持学生身份认证，不再支持教师身份认证。

### 6.2 题库练习

文件：`src/pages/PaperPages.jsx`

包含：

- 试卷列表筛选：文化课/专业课、专业/科目、来源、分类、年份。
- 试卷状态：`未开始`、`进行中`、`已完成`。
- 进行中的试卷展示“已用时间”，不展示“剩余时间”。
- 试卷答题页有本次已用时间统计。
- 试卷解析页展示答题结果、解析、题号导航。

注意：

- 试卷只有题目、题量、时长、得分、状态等字段，不应额外展示试卷介绍字段。
- 学习中心中的个人练习字段应与题库练习保持一致。

### 6.3 考试中心

文件：`src/pages/ExamPages.jsx`

包含：

- 学校为学生安排的模拟考试，包含文化课和专业课。
- 考试详情、考试答题、考试解析、成绩排行。
- 考试卡片按钮使用“进入考试”。
- 实际进入答题动作使用“开始考试”。

考试状态与课程状态不同，可保留独立状态：

- `未开始`
- `进行中`
- `评审中`
- `已公示`
- `已结束`

### 6.4 学习中心

文件：`src/pages/LearningPages.jsx`

包含：

- 游客态、注册用户态、班级学生态。
- 当前学校班级展示。
- 课程。
- 试卷练习。
- 作业。
- 错题本和学习记录。

近期已调整：

- 考试中心个人考试统计去掉“待关注”。
- 题库练习列表字段统一为“已用时间”。
- 课程和课时状态统一为：`未开始`、`进行中`、`已完成`。

### 6.5 课程详情和课时学习

文件：`src/pages/LearningPages.jsx`

课程详情包含：

- 详情
- 目录
- 试卷
- 课件
- 答疑

课时类型：

- 微课
- 慕课
- 音频
- PDF
- PPT
- 富文本

课时进度规则：

- 非音视频课时：PDF、PPT、富文本打开查看详情即视为完成。
- 音视频课时：微课、慕课、音频在打开、切换课时、关闭浏览器或播放完成时上报当前播放时间节点。
- 音视频进度：按 `上报时间 / 总时长` 计算。
- 上报时间大于等于课时时长时，课时状态为 `已完成`。

注意：

- 这些规则只应出现在原型标注中，不应作为学生可见说明直接展示。
- 学生可见文案使用“已学习 xx / xx”，不要使用“已上报”。

### 6.6 班级答疑

文件：`src/pages/LearningPages.jsx`

当前规则：

- 提问本身没有标题。
- 答疑记录不设置提问标题，字段包括：时间、发送人、答疑信息。
- 后续新增“关联课程/课时”字段。
- 答疑列表以关联课程/课时识别记录。
- 展示老师是否回复。
- 点击查看记录后，可以回复或追问。

### 6.7 个人中心和入校申请

文件：`src/pages/ProfilePages.jsx`、`src/components/ui.jsx`

当前规则：

- 入校申请弹窗由 `SchoolApplyModal` 实现。
- 只支持学生身份认证。
- 课程试看页和 `#/school-apply` 链接会打开同一个全局弹窗。

### 6.8 运营后台

文件：`src/pages/AdminPages.jsx`

包含：

- 平台资讯管理。
- 首页推荐课程管理。

资讯管理：

- 新建、编辑、预览为独立页面，不是弹窗。
- 资讯不提供封面。
- 不提供排序，按发布时间倒序。
- 有分页。

首页推荐课程管理：

- 推荐课程从课程库选择。
- 课程库弹窗只展示已上架课程。
- 课程库弹窗支持分页。
- 模糊搜索范围：课程名称、课程 ID、创建人。
- 推荐课程最多 12 个。
- 推荐课程设置“试看课时数”。
- 试看时长固定为每课时 5 分钟。
- 推荐课程列表不展示更新人。

## 10. 已知风险和后续建议

### 10.1 状态字段需要集中管理

当前最大维护风险是状态字段分散。建议优先抽状态常量和 helper。否则多页面复用同一业务状态时，容易再次出现文案和判断不一致。

优先级：高。

### 10.2 mock 数据和真实字段需对齐

目前很多字段是为原型展示临时组织的。接后端前，需要逐页确认字段来源：

- 课程
- 课时
- 试卷
- 考试
- 答疑
- 入校申请
- 推荐课程
- 平台资讯

优先级：高。

### 10.3 业务页面不展示研发说明

已经出现过把研发规则、数据来源和功能解释放进业务页面的问题。后续此类内容优先维护在 PRD、字段清单和项目文档中；只有确认后且能直接指导设计或开发的内容，才使用 `DesignAnnotation` 放入独立浮层。

优先级：中。

### 10.4 需求说明统一回到文档

`PrototypeNote` 当前是兼容旧废案的空组件，`PageHeader desc` 不再渲染。接手后应优先核对 PRD、页面字段清单和后台扫描结果；新增标注不得包含废案、功能介绍、后台猜测、待办或权限自证。

优先级：高。

### 10.5 部分开发侧修改未同步到原型

开发过程中存在一些产品或后台设计调整已经被讨论或记录，但由于时间原因没有全部同步到当前前端原型。当前原型不能视为完整需求源，应结合以下资料一起核对：

- 最新产品修改单。
- 后台设计稿或后台字段说明。
- 研发侧实际接口字段。
- 本项目的 `PROJECT_MAP.md`。
- 本交接文档中的“已知风险”和“状态与数据约定”。

接手人继续推进前，建议先整理一份“已进原型 / 未进原型 / 待确认”的差异清单，再决定是否补原型或直接进入研发实现。

优先级：高。

### 10.6 后台运营只是原型

后台运营页面目前没有真实增删改状态持久化。按钮和弹窗用于展示交互逻辑，不会改变 mock 数据。

优先级：中。

### 10.7 不考虑移动端

当前评审口径是不考虑移动端。页面仍有响应式类名，但主要按桌面端原型验收。

优先级：低。

### 10.8 班级管理权限归属存在后台风险

当前后台实现里，班级管理存在“谁创建归属谁”的口径，且现阶段后台权限不再调整。若教师端不提供建班和分班，教师必须先进入后台完成配置，教学流程无法在教师端独立闭环。因此一期采用最小迁移方案，只将教师开始教学前必需的班级和学生配置移入教师端。

当前设计交接口径：

- 班级属于学校组织配置，归属应以学校为主，而不是以创建人为主。
- `createdBy` 应作为审计字段，不应作为班级业务归属的唯一判断。
- 教师端一期增加最小班级配置：新建班级、添加学生、单人调整班级和批量分班。
- 教师完成上述配置后，可继续进行班级派课、班级作业、学情、答疑和批阅，形成教学闭环。
- 班级冻结/解散、教师角色授权、学生审核/停用、跨校转移仍归学校管理后台。
- 原型使用浏览器本地数据模拟建班和分班，刷新后保留；未接入真实接口、数据库和后台权限。

后续研发建议：

- 班级主归属字段建议为 `schoolId`。
- 教师可见班级建议来自教师-班级关系，例如班主任、任课教师、教务管理员角色。
- 学生可见课程、作业和题库权限建议来自学生-班级关系和班级绑定专业大类。
- 当前教师端迁移方案是后台权限无法调整时的一期交付措施。后续若重构权限，应再评估是否将建班和分班收回学校教务角色。

优先级：高。该问题已通过前台最小功能迁移解除一期交付阻塞，但后台班级归属规则仍需后续研发处理。

## 11. 接手建议

建议接手人按以下顺序熟悉：

1. 运行项目，打开 `#/`，用演示控制切换三种身份。
2. 查看 `src/App.jsx`，确认路由结构。
3. 查看 `src/data/mockData.js`，理解所有 mock 数据。
4. 查看 `src/components/ui.jsx`，理解全局布局、角色、标注和入校申请弹窗。
5. 查看 `src/pages/LearningPages.jsx`，这是当前最大、最复杂的业务页面。
6. 查看 `src/pages/PaperPages.jsx` 和 `src/pages/ExamPages.jsx`，确认试卷和考试闭环。
7. 查看 `src/pages/AdminPages.jsx`，确认运营后台范围。

建议优先重构项：

1. 抽状态常量和状态 helper。
